# 深夜书房 · 使用说明

一只住在桌面上的角色：会呼吸、会眨眼、记得你多久没喂她，还能和 QQ 里的机器人联动，
说话时桌面上的大肥鱼桌宠也会跟着开口。两台机器都装的话，会互相发现、握手、串门。

---

## 一、三分钟跑起来

### 1. 起看板服务

```
双击  room-pet\启动看板.bat
```

它做两件事：起本地服务（8796）→ 打开浏览器页面。

### 2. 换成桌面窗（可选）

```powershell
cd room-pet
python app_shell.py          # 置底，像壁纸
python app_shell.py --top    # 置顶，像桌宠
```

快捷键：

| 热键 | 作用 |
| --- | --- |
| `Ctrl+Alt+D` | 切置底 |
| `Ctrl+Alt+T` | 切置顶 |
| `Ctrl+Alt+Q` | 退出 |

开机自启：`python app_shell.py --install`

## 三、和 QQ 机器人联动

前提：qq-bridge 在跑（`qq-bridge`），看板服务在跑。

```
QQ 里发消息  → 桥接收到 → 看板轮询到"有新消息" → 切「思考」
她回复       → 看板读到"已发送"      → 切「说话」+ 气泡 → 2 秒后待机
```

不需要改桥接代码：看板每 1.2 秒读一次 `/api/status` 和 `/api/socialV2/states`，
再加一条日志尾巴检测（`state/bridge.log` 里的「已发送」）。

**信号说明：**

| 信号 | 触发 |
| --- | --- |
| 未读总数增加 | 思考 |
| 日志出现「已发送」 | 说话 |
| 20 秒没有新动作 | 回待机 |

**桌宠右键菜单会多一项「书房模式」**，点它打开书房页面。

## 五、在线朋友（跨机器串门）

### 第一次：填配对码

```
打开 room-pet\settings.json
"lan": { "enabled": true, "code": "7fea85", "mirror": true }
```

两台机器填**同一个** `code`，改完各自重启看板服务。

### 第二步：握手

```
页面右上角「在线朋友」→ 看到对方 → 点「同意」
（控制台「桌面看板」页里也有一份同样的列表）
```

同意之后：

```
· 她说话时，会镜像给对方（对方桌宠也开口）
· 对方说话时，你的宠物会"转头看过去"并显示「XX 说：…」
```

### 第三步：主动说一句

```
点「说一句」选中朋友 → 输入框输入 → 发送
```

### 列表里的词

| 词 | 含义 |
| --- | --- |
| 待确认 | 发现了但还没握手，不会互推 |
| 已接通 | 握手完成，可以互推、互发消息 |
| 断开/忽略 | 撤销握手，之后不再互推 |

握手记录存在 `settings.json → lan.approved`，重启不丢。

## 五·补 跨家庭网络（不在同一个路由器下）

局域网广播出不了 NAT，所以两家路由器后面的两台机器要用**手动添加**。

### 路线 A：Tailscale（推荐，5 分钟）

```
1. 双方安装 Tailscale 并登录同一个 tailnet（或用共享节点邀请对方）
2. 各自拿到 100.x.y.z 地址（Tailscale 自己的虚拟内网 IP）
3. 在书房页面「在线朋友」→ 手动添加里填：  100.x.y.z:8796
4. 双方配对码要一致（settings.json → lan.code）
```

**为什么可行：Tailscale 把两台机器放进同一个虚拟内网，`100.64.0.0/10` 的地址互相可达；
我们的服务本来就监听 `0.0.0.0`，所以直接连得上。**

### 路线 B：公网映射（frp / cloudflared）

```
cloudflared tunnel --url http://127.0.0.1:8796
→ 得到一个 https://xxx.trycloudflare.com
→ 对方在「手动添加」里填： xxx.trycloudflare.com:443
```

**这条会把服务暴露到公网，必须先打开 `publicMode`：**

```json
"lan": { "code": "至少16位的长令牌", "publicMode": true }
```

`publicMode` 开启后：

```
· 配对码短于 16 位 → 所有外部请求直接拒绝
· 每个 IP 每分钟最多 60 次请求，超出回 429
· 回环地址（自己机器）不受影响
```


### 路线 D：公网直连（STUN 打洞，不用装客户端、不用服务器）

已经在页面和「桌面看板」里做好：朋友列表下面的「公网直连（跨网络）」。

**步骤（两边都要做）：**

```
① 各自点「生成邀请码」→ 复制（形如 eyJ2IjogMSwgImlwIjog...）
② 把码发给对方（QQ/微信都行）
③ 各自把对方的码粘进「粘贴对方邀请码」→ 点「连接」
④ 两边都点；25 秒内连通就显示「已连接 ip:port」
```

**通了之后：**

```
· 对方说话：你这边的宠物转头 + 气泡「名字 说：…」
· 你说话：镜像会自动走这条 UDP 通道（不走 HTTP）
· 每 10 秒一个保活包，断了会掉回「未连接」
```

**已知限制（必须知道）：**

```
· 对称型 NAT（部分运营商/企业网/校园网）打洞一定失败 → 换 Tailscale
· 邀请码里的端口是 NAT 映射端口，通常几分钟有效，超时重新生成
· 双方都在 CGNAT（运营商大内网）时也打不通
```

**命令行走这套（不想点页面）：**

```
GET  /punch/invite                  # 拿自己的邀请码 + 公网地址
POST /punch/connect {"invite":"…"}  # 连对方
GET  /punch/status                  # 看是否已连接、对方地址
POST /punch/say     {"text":"…"}    # 走打洞通道发一句
```





### 在线状态（三种）

朋友列表里不再只有“已接通”，而是分三种：

| 显示 | 含义 | 判据 |
| --- | --- | --- |
| 在线（绿） | 对方页面开着 | 对方 `/presence` 心跳为 true |
| 未开页面（灰） | 对方的看板服务在跑，但页面关着 | 心跳为 false |
| 待确认（黄） | 还没握手 | 未同意 |
| 从列表消失 | 服务停了 | 12 秒没心跳 + 退出时广播 bye |

机制：

```
页面每 8 秒 POST /presence {alive:true}
关闭页面时用 sendBeacon 发 {alive:false}（不会因为关页丢包）
服务退出时 UDP 广播 rp-bye，对端立刻移除
没收到 bye（被强杀）→ 12 秒 TTL 自动移除
```

**实测：**

```
开页面   → 对端 page: true   → 显示「在线」
关页面   → 对端 page: false  → 显示「未开页面」
杀进程   → 15 秒后从列表消失（12 秒 TTL + 5 秒 GC 间隔）
```

### 配对码（可视化，不用改文件）

朋友列表上方有一块「配对码」：

| 控件 | 作用 |
| --- | --- |
| 显示框 | 当前配对码（只读，点「复制」可直接发人） |
| 换一个 | 生成一个随机的（局域网 6 位 / 公网模式 16 位） |
| 用对方的码 | 粘贴朋友给的码，直接把自己的改成它 |

**改完的效果：**

```
· 立即生效（内存里的发现/打洞都换用新码，不用重启）
· 已握手的朋友会被清空（换了码就是换了一批人）
· 手动添加的地址也会清空（它们依赖旧码的信任）
· 写进 settings.json，重启后仍是新码
```

**公网模式的约束：**

```
publicMode = true  → 配对码至少 16 位，6 位会被拒绝（need: 16）
publicMode = false → 至少 6 位
```

接口：

```
GET  /pair/info                 # code / length / publicMode / name / instance
POST /pair/code {"code":"…"}    # 改码（太短回 too-short + need）
POST /pair/mode {"publicMode":true|false}   # 开关公网模式
```

### 自动选路线

页面和控制台打开时会自动问一次 `/net/advice`，据本机情况给出推荐：

| 本机情况 | 推荐 | 界面表现 |
| --- | --- | --- |
| 有 Tailscale 且拿到 100.x | **用 Tailscale** | 绿色横幅「已检测到 Tailscale，建议直接用它连」+「复制 100.x:8796」；打洞控件默认收起，点「仍然尝试打洞」展开 |
| 装了 Tailscale 但没 100.x | 先修 Tailscale | 横幅提示「打开并登录，状态 Connected 后刷新」 |
| 没装 Tailscale | **先试打洞** | 横幅「没装 Tailscale，先试打洞」；打洞控件正常显示 |

后端：

```
GET /net/advice
{
  "recommended": "tailscale" | "tailscale-offline" | "punch",
  "address": "100.x.y.z:8796" 或 null,
  "tailscale": {"installed": true, "ip": "100.x.y.z", "exe": "…"},
  "title": "…", "detail": "…"
}
```

### 打洞失败时会发生什么

点「连接」25 秒内没通，面板会直接展开一张**处理建议卡**（页面和控制台都有）：

| 你的情况 | 卡片给的建议 |
| --- | --- |
| 没装 Tailscale | 五步：下载 → 登录同一 tailnet → 拿到 100.x → 双方手动添加 `100.x:8796` → 配对码一致 |
| 装了但没拿到 100.x | 提示先打开 Tailscale 并登录，再看状态是否 Connected |
| 装了且已有 100.x | 直接显示「复制我的 Tailscale 地址」，点一下复制 `100.x:8796` 发给对方 |

后端对应字段：

```json
POST /punch/connect → 失败时
{
  "ok": false,
  "error": "timeout",
  "advice": {
    "code": "suggest-tailscale" | "use-tailscale" | "tailscale-offline",
    "title": "打洞失败：你们的 NAT 类型不支持直连",
    "steps": ["…", "…"],
    "tailscaleIp": "100.x.y.z"        // 仅 use-tailscale 时有
  }
}
```

## 十、伪 L2D（书房里的"会转头"版本）

打开 `l2d-lite.html`（书房页面底部也有「伪 L2D」入口）。

**它不是真 Live2D，而是用两张同源图层做的错觉：**

```
body 层：整张立绘，做呼吸（纵向 ±0.6%）+ 整体左右轻摆
head 层：同一张图，用 CSS mask 裁出头顶 ~34%（渐变羽化接缝）
        跟随鼠标做 ±14px 横向位移 + ±3.2 度旋转，带 0.12 秒滞后
点击    ：挤压回弹（scaleY 压扁再弹）
状态    ：SSE 接 /events，思考/说话时轻微前倾 + 气泡
```

**效果边界：**

| 有 | 没有 |
| --- | --- |
| 呼吸、轻摆、跟随鼠标转头、点击弹跳、气泡联动 | 眨眼、口型、表情切换、头发分束 |

**因为没有分层美术（眼睛/嘴/头发是合并的），眨眼和口型做不了 —— 那是真 L2D 才能做的。**

对比三条路：

| 方案 | 页面 | 效果 |
| --- | --- | --- |
| 帧动画 | `index.html` | 18 张整图切换，交互最全 |
| 伪 L2D | `l2d-lite.html` | 会呼吸、会转头，动作连续 |
| 真 L2D | `l2d.html` | 骨骼驱动，但是 Hiyori 占位模型 |

## 十二、语音与嘴型（从「鲸伴」拆出来的两段）

参考项目：[鲸伴 jingban-desktop](https://github.com/chengjiang-zi/jingban-desktop)（MIT，作者澄江子）
拆了它的两段实现：**音频驱动嘴型** 和 **TTS 接口形态**；记忆那段留在后端。

### 1. 嘴型：真实音量驱动

算法直接沿用鲸伴的 RMS 公式：

```js
mouth = clamp((rms - 0.008) * 7, 0, 1)
```

**实现位置：** `l2d-layers.html`

```
AnalyserNode → getFloatTimeDomainData → RMS → 嘴部图层 opacity 交叉
说话时用真实音量；不说话时回落到正弦（点「说话口型」看效果）
```

### 2. TTS：本地合成，不需要 API Key

```
GET /tts?text=…  →  返回 audio/mpeg
  引擎：edge-tts（微软免费音色，本机合成）
  音色：zh-CN-XiaoyiNeural
  缓存：tts-cache/<sha256前24位>.mp3，同句不重复合成
  实测：15~25 KB / 句，3 秒左右
```

**页面用法：** 底部输入框输入一句 → 回车 → 播放 + 嘴型跟着动 + 字幕。

### 3. 记忆：轻量版

```
GET    /memory          → {items:[{id,text,tag,at}]}
POST   /memory {text,tag}  → 追加（上限 500 条）
DELETE /memory?id=…     → 删除
存储   room-pet/memory.json
```

> 鲸伴用的是 Mem0 + BGE 检索；这里先用 JSON 存储，够书房场景用。
> 真要做语义检索，再把 Mem0 接上。

### 和鲸伴的差距（明确写出来）

| 能力 | 鲸伴 | 我们的书房 |
| --- | --- | --- |
| TTS | Breeze-TTS-2 本地权重 | edge-tts（在线、免费） |
| ASR | faster-whisper 本地 | ❌ 还没接 |

### 两个来源：网页版 / 电脑版

| 来源 | 做法 | 时延 | 能看到什么 |

| 网页版 | CDP 打开 douyin.com，读卡片 DOM | 实时（2 页约 30 秒） | 标题 / 作者 / 赞 / 时长 / 发布时间 / 真链接 / 评论 |

电脑版为什么不是 CDP：

```
· 客户端是 Chromium 壳（resources/app.asar），但 douyin.exe 是引导壳，

· UIA 也不可用：ElementFromHandle 返回 E_NOINTERFACE（应用没挂无障碍桥）
→ 所以走「截图 + 本地视觉」这条路，验证过能准确读出标题
```

用法：

```

  结果写 douyin/desktop.json，页面按文字行展示
命令行单跑：python douyin_desktop.py --capture
纯探针：    python douyin_desktop.py --probe
```

建议：实时刷用网页版；电脑版适合「我现在就要看客户端里有什么」的单次确认。

电脑版的两种用法：

```
单次：  python douyin_desktop.py --capture            # 截一帧 + OCR（0.4 秒）
连续：  python douyin_desktop.py --watch 2            # 每 2 秒一帧，只打印新出现的行

### 互动结构打分（借 dsh-douyin-scroll 的思路）

刷到的高赞视频只是「点赞多」，看不出为什么值得看。点「补互动数据」会给这些视频补
收藏/转发/评论/播放，并算三个比值：

```
收藏/点赞  高 → 有保存价值（教程、攻略、美食）
转发/点赞  高 → 想转给别人（好笑、共鸣）
评论/点赞  高 → 引发讨论
结构分 = 点赞基础分 + 藏比×8 + 转比×10 + 评比×6，时长 <12 秒再 ×0.6
```

数据来源：视频页里调签名接口 `/aweme/v1/web/aweme/detail/`（bdms 自动补 a_bogus），
一条约 1 秒，默认补前 10 条，结果回写 `douyin/latest.json` 并按结构分重排。

实测（2026-11-13）：

```
7697926023714737408  赞 1453.9万 藏 501.9万 转 665.4万 → 藏34.5% 转45.8% 评1.5%  分10.43
7694206162778017058  赞  50.1万 藏  12.5万 转  15.4万 → 藏24.9% 转30.7% 评1.3%  分8.14
7694869545252687130  赞  14.5万 藏   2.1万 转   3.1万 → 藏14.5% 转21.6% 评1.4%  分6.40
```

接口：`GET /douyin/enrich?top=10`；脚本：`python douyin_enrich.py --top 10 [--dry]`

### 一键流水线 + 语义判断

刷抖音页新增按钮「一键刷（刷+补数据+判断）」，串行跑三步：

```
douyin_browse.py  → 抓候选（复用已登录窗口的调试端口，等卡片出现再抓）
douyin_enrich.py  → 补互动数据（签名接口 aweme/detail），算藏/转/评比值和结构分
douyin_judge.py   → 语义判断：规则定档 + 模型写一句理由
```

实测耗时：抓取 20 秒 + 补数据 9 秒 + 判断 10~34 秒 ≈ 1 分钟一轮。

判定规则（3B 模型不足以自己定档，改成规则兜底）：

```
结构分 ≥9   → 值得看
结构分 6~9  → 顺带一看
结构分 4~6  → 判断不了
结构分 <4   → 不推荐
理由：模型用一句 25 字以内中文写，只准引用数据；出现「一句话/证据/根据」等字样就丢弃，
      退回规则理由（例如「收藏率 34%，典型的值得存下来的内容」）
```

接口：

```
GET /douyin/pipeline?pages=2&top=5    一键跑
GET /douyin/enrich?top=10             只补数据
python douyin_judge.py --top 5 [--dry] 只判断
```

### 评论 status 的含义（实测记录）

```

status=2  仅自己可见 / 待审核（列表里能看到，但别人看不到）—— 新号评论经常这样

```

```

  "自己视频下留个爪印"        st=3

你自己的视频（7700660682928967397）
  "跨次元聊天这题材我熟"      st=2   ← 你看不到

### 抖音登录（控制台）

刷抖音页顶部「抖音登录」一行：

```
[刷新状态] [显示二维码] [同步 cookies 到桥接] [退出登录（换号用）]
已登录：鱼（7707362509204423739）
手机号/账号 [____]  密码 [____] [密码登录]   短信验证码 [____] [提交验证码]
扫码（手机抖音扫）  验证码 / 页面（点图 = 在页面同位置点一下）
```

实现（douyin_login.py）：

```
status   从页面调 /aweme/v1/web/user/profile/self/ 判断登录态（uid / 昵称）
qr       打开 douyin.com → 点「登录」→ 找弹层里的大方形 canvas/img → 截那一块
shot     截当前视口（验证码就在这张图上）
click    把控制台图上的点击换算成页面坐标 → CDP 派发鼠标事件（滑块验证码用）
password 切「密码登录」页签 → 填账号密码（走原生 setter + input 事件）→ 点登录
sms      把短信验证码填进最后一个输入框
sync     跑 export_cookies.py，把当前登录态写成 Netscape cookies.txt 给桥接
logout   点头像 → 退出登录（换号/二维码登录前要先退）
```

**验证码为什么不做自动过**：滑块/点选是对抗式验证，自动破解既不稳也有风险；
这里改成「截图 + 你点一下」，点击坐标由服务端换算后派发给页面，等价于你自己在浏览器里点。

**已知限制**：已经登录时点「显示二维码」拿不到二维码（页面上根本没有「登录」按钮，
返回 `clicked: no-login-btn`）。要扫码得先点「退出登录」。

接口：GET /douyin/login/status；POST /douyin/login/{qr|shot|click|password|sms|sync|logout}
图片：GET /douyin/login/qr.png、/douyin/login/shot.png
