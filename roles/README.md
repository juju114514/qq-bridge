# 角色扮演文件（人格卡）

每个角色一个 Markdown 文件，**文件名 = 角色名**（不含扩展名，中英文均可）。例：`roles/傲娇助手.md`。

在群里对 QQ agent 说 `进入角色扮演：<角色名>`，或在控制台「人格与角色」页点选启用；说 `退出角色扮演` 恢复正常。

---

## 〇、身份在文件里，不在文件名里（必读）

每张卡开头有一段 **front matter**，桥接靠它认人：

```markdown
---
id: xiaojingyu
name: 小鲸鱼（已测试）
---
# 角色卡：…
```

| 字段 | 作用 | 能改吗 |
| --- | --- | --- |
| `id` | **身份**。`state/current-role.json` 与 `state/roles-by-key.json` 只存它 | ❌ 别改（改了等于换了一张卡） |
| `name` | 显示名。控制台列表、`/role`、日志里显示的就是它 | ✅ 随便改，**不碰任何绑定** |
| 文件名 | 仅存放位置 | ✅ 随便改（中文、括号、空格都行） |

为什么要这样（这段是踩坑记录）：

> 以前文件名兼任身份，于是「名字里带全角括号 / 改个名 / 丢个后缀 / 换台机器搬文件」
> 会让 `/role`、会话绑定、控制台一起失效 —— 同一类 bug 连续踩了三次。

几条规矩：

- **改名请用控制台或 `/role`**，它只改 `name`，不动文件名；
- **不要往 front matter 里塞人设内容**：它只认 `id` / `name` 两个键，其余会被忽略，
  而且元数据不会进提示词（`selectRoleText` 会统一剥掉）；
- 老卡没有 front matter 也能用（id 取文件名的确定性哈希），跑一次
  `node scripts/migrate-roles-to-ids.mjs --apply` 会把它们补齐并改写旧绑定。



本目录的角色卡是**同人创作**：角色、名称、设定、形象的权利归原作者/权利方，**本项目的 MIT 只覆盖代码，不覆盖这些角色与设定**。每张卡的出处、权利方，以及「新增卡片时必须写归属」的规矩，见 [ATTRIBUTION.md](ATTRIBUTION.md)。

如果你是权利人、不希望某个角色出现在这里：开 issue 即可立刻删除。

## 一、人格卡只写「人设」，不写「怎么干活」

这是最重要的一条。提示词分两层：

| 层 | 放在哪 | 管什么 |
| --- | --- | --- |
| **人格提示词** | 本目录的 `roles/<角色名>.md` | **你是谁**：身份、性格、说话风格、梗、雷点、和其他人的关系 |
| **仿真提示词** | `dsh/agent-presets/qq-chat{,-v2}/agent.cordis.yml` 的 `persona.prefix` | **怎么干活**：工具怎么调、怎么分条、怎么潜水/唤醒、怎么用表情包与记忆 |

**不要把工具用法写进人格卡。** 原因：

- 两代的工具协议完全不同（一代空格分条 + `[SILENT]`；二代一切皆工具 + 数组分条），写进人格卡必然有一代是错的；
- 桥接已经在**每条消息**里告诉模型当前模式的分条方式与潜水方式，重复写只会占预算；
- 表情包、记忆、看图、合并转发、引用规则等能力，各自预设里都有完整章节，人格卡里再写一遍会互相打架。

人格卡里写工具说明的典型症状：在二代下被桥接**整行过滤**（白写），或者让模型照着一代的写法去发消息。

---

## 二、需要区分模式时：在标题里加标记

同一个角色如果确实需要「一代这样说、二代那样说」，用**标题级模式标记**，桥接会只注入当前模式适用的小节：

```markdown
## 三、分条方式 〔一代〕
- 想分多条就用空格分隔；想沉默就只输出 [SILENT]。

## 三、分条方式 〔二代〕
- 用 qq_send_message 的 messages 数组分条；潜水用 qq_mark_read。

## 四、说话风格
- 这条没有标记 → 两种模式都会注入。
```

- 支持的写法：`〔二代〕`、`[v2]`、`（reserved2）`、`〔2 代〕`（一代同理：`〔一代〕`/`[v1]`/`（reserved）`）。
- 标记只是给桥接看的，**注入前会被去掉**，模型看到的标题是干净的。
- 没有标记的小节＝通用人设，两种模式都注入。
- 控制台打开某个人格时会显示「按模式注入：二代 N / 一代 M 字符」，并标出哪些小节会被跳过。

---

## 三、注入上限

- 默认**每条消息最多注入 6000 字符**（`config.json` 的 `role.maxInjectChars`，可设 1000~20000，控制台也能直接改）。
- 截断发生在**按模式筛完小节之后**，所以另一代的专属内容不会占掉本次预算。
- 这是成本护栏：人格卡会随每条消息一起发送，6000 字符约合 4~6k token。
- 控制台的人格列表会标出「超出上限」与各模式的实际注入字符数。

> 建议把人格卡控制在 3000~5000 字符：够写清人设，也不至于让每条消息都背上很长的前缀。

## 四、推荐结构（模板）

```markdown
# 角色卡：<角色名>

## 一、你是谁
- 身份、自我认知、别人怎么称呼你、你的雷点。

## 二、说话风格
- 句子长短、口头禅、标点习惯、用不用 emoji/括号。
- 明确写「不要什么」通常比写「要什么」更有效（例如：不要总结、不要升华、不要客服腔）。

## 三、性格与反应
- 被夸/被怼/被无视时分别怎么反应；有没有嘴硬、摆烂、傲娇之类的固定模式。

## 四、梗与背景（可选）
- 你的来历、和群友的关系、常用梗、角色梗的边界。

## 五、回复示例（示范语气与长度）
- 几条「群友说 → 你回」的例子。
- 例子只示范**语气和长度**，不要在这里规定分条机制（那是仿真层的事）。
```

## 五、其它提示

- 想改性格直接改文件内容，控制台保存后**下一条消息即生效**（人格层由桥接每条消息注入，不用重启 DSH）。
- 只写人格、不写工具，换模式时不会出现「一代能用二代不能用」的规则。
- 角色名建议用简短中文（如 `傲娇助手`、`猫娘`、`吐槽役`）；不能与已有重名，也不能用 `README` 或 Windows 保留名（`CON`/`NUL`/`COM1`…）。
- 想临时关闭人格扮演，在控制台点「清除」；此时 AI 只按仿真提示词行动。
