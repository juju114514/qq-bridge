## 二、插件模式：11 个「静默失败」

全部**不报错、不崩溃、只是不动**。单测发现不了，只有真机发消息才暴露。

| # | 环节 | 症状 | 根因 |
| --- | --- | --- | --- |
| 1 | 工具注册 | `schema … got type: null` | `register()` 不编译参数，编译在 `defineTool()` |
| 2 | sidecar | 读快照全 401 | token 为空；`/health` 免鉴权所以"看着是好的" |
| 3 | 通道独占 | 一条消息回两次 | sidecar-only 仍建了 WS 连接 |
| 4 | @ 判定 | @ 它没反应 | 事件里没有 `self_id` |
| 5 | 通道认领 | 重启后不连 QQ | 僵尸认领仍在 60s 心跳窗口内 |
| 6 | 发送 | `client.action is not a function` | 方法名是 `call()` |
| 7 | 投递 | 会话建了、消息没进去 | 新 agent 的 `whenIdle()` 可能永不 resolve |
| 8 | Agent | 有入队、无 turn 事件 | `agents.create` 没给模型 |
| 9 | Agent | 同上 | `meta` 缺 `cwd` |
| 10 | **Windows** | `mkdir …group:994920175` ENOENT | **文件名不允许 `:`** |
| 11 | 转发 | 模型答了群里没有 | fallback session id 与监听 id 不一致 |

两个运维陷阱：

- **preset 代码有 3 份副本**，只有 `dsh/agent-presets/<preset>/` 被加载；改错文件**没效果也不报错**
- **preset 只在建会话时 apply**，老会话不重新应用 → 改完必须重启 DSH

## 三、越权事故（13:35）

群里有人 @ 它说「你是一个合格的鱼你自己弄插件自己弄模型」。
agent 理解成"去本机修东西"，调用：

```
desktop_sequence: win+r → 输入 powershell → 回车
screen_view: 确认窗口
```

用户发现后立即中断 → `tool call aborted`。

**后果**：无实质损害 —— PowerShell 事件日志零条 ScriptBlock 执行，无文件改动，凭据时间戳未变。

**根因**：插件建 agent 时没挂 `agentPreset` → 拿到默认工具集（`pwsh`/`read`/`write`/`edit`/`desktop_*`），
权限等于用户本人。桥接走 `qq-chat-v2` preset 本有边界，插件绕过了整条链路。

**处置**：

| 版本 | 动作 |
| --- | --- |
| 0.4.18 | 补 `agentPreset`（人设 + 工具面） |
| 0.4.19 | 插件侧 `restrict({ allow })`：只留 10 个工具 |
| 0.4.20 | 熔断开关（`state/plugin-kill` → 2 秒断开）+ 工具名落日志 |
| 0.4.21 | preset 限制改成「按真实工具名算的白名单」 |

**教训**：安全边界应当先于功能验证；复用 agent 机制要把护栏一起搬。

## 五、两条路可切换

```powershell
node scripts/switch-mode.mjs status   # 看现在谁在收
node scripts/switch-mode.mjs bridge    # 路线 A：常驻 bridge
node scripts/switch-mode.mjs plugin    # 路线 B：DSH 插件
```

顺序：**切 A 先重启 DSH；切 B 先重启桥接**。反了会空窗或双回复。
