## 一、要解决什么

SnowLuma 的许可（源码可见、非商业）里有一条可能让本项目被要求改名或下架的条款：

| 条款 | 原文要点 | 本项目的处境 |
| --- | --- | --- |
| §4(a) | 「Commercial Use of the Software **in any form** is PROHIBITED」 | 本项目免费、不卖服务 ⇒ 不触发 |
| §4(b) | 不得「基于本软件」开发、发布或分发**另一个项目** | **这是唯一有真实不确定性的条款**：QSH 确实是"另一个项目" |
| §3(d) | 公开发布「修改版或衍生版」须事先书面许可 | 不在仓库内包含/分发 SnowLuma 源码与二进制 ⇒ 不构成衍生版 |
| EULA §5.4 | 不得把专有组件并入安装包/Docker/自动化部署 | 已升级为设计不变量 **L6**：只探测、不安装、不程序化启停 |

## 二、两种读法与最终立场

- **宽松读法**：§4(b) 紧接商业限制，意图是堵「把商用包成周边项目绕过 §4(a)」，不禁止一切互操作工具。
- **严格读法**：§4(a) 的 "in any form" 已覆盖伪装商用 ⇒ 宽松读法会让 §4(b) **没有任何独立适用范围**，
  违背「同一份许可内部应作一致解释」。

**采纳严格读法作为工作假设**（不是法律结论）。理由三条，从弱到强：

1. 解释许可最忌讳让某条款**空转**——若宽松读法成立，§4(b) 就是一句废话；
2. 同一份许可内部应一致解释：§4(a) 已经用 "in any form" 兜住商用，§4(b) 只剩字面含义可用；
3. §2 授予的权利是 **revocable**，EULA §8 允许著作权人**单方面更新条款** ⇒ 把项目命脉押在
   「对方不会翻脸」上，风险不对称。

> 注意：文档对外仍**如实保留**「两种读法」的表述（见 NOTICE.md），因为那是客观存在的分歧；
> 但**项目内部的行动假设是严格读法**。两者不矛盾：承认不确定性 ≠ 按最松的解释行事。
