## v0.4.1 · `channel.enabled` —— 让 sidecar 把通道让给插件

> 小更新。默认行为不变（`channel.enabled` 默认 `true`，照常连网关）。

### 解决什么

0.4.0 发布插件模式后有个卡点：插件和常驻 bridge **只能有一个收消息**，
但 bridge 没有"我不收消息、只当 sidecar"的开关 —— 想试插件就得把 bridge 整个关掉，
而那意味着记忆、记账、控制台全都没了。

### 现在怎么做

```jsonc
// sidecar 机器上的 config.json
{ "channel": { "enabled": false } }
```

启动日志：

```
[bridge] sidecar-only 模式（channel.enabled=false）：不连接 QQ 网关，也不占用通道认领
```

- 控制台、sidecar 契约、定时器**全部照常**
- `state/channel-mode.json` 不再生成 → 插件才能拿到通道（`claim(plugin) → ok=true`）
- 切回 bridge：改回 `true` 并重启

### 验证

真机实测：sidecar-only 启动后 `channel-mode.json` 不存在、插件侧 `claim` 成功（`reason=free`）；
改回 `true` 后 bridge 重新认领（`reason=free`）。审计 127/127。

详见 [docs/guides/PLUGIN-MODE.md](https://github.com/juju114514/qq-bridge/blob/main/docs/guides/PLUGIN-MODE.md)。
