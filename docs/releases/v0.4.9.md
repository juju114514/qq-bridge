## v0.4.9 · 真正的根因：工具没经过 `defineTool()` 编译

### 现象

```
Invalid schema for function 'qqb_get_prompt':
schema must be a JSON Schema of type: 'object', got 'type: null'
```

改完名**还是同样的错** —— 证明名字不是原因。

### 根因

宿主 `ctx.tools.register()` **不编译 schema**，只校验 `output`。编译在 `defineTool()` 里：

```js
function defineTool(options) {
  const parameters = parameterSchemaSpecToJsonSchema(options.parameters);  // ← 这里才补 type:'object'
}
```

我们一直把裸对象直接丢给 `register()`，于是供应商收到的是 `{ chat_id: {...} }`，没有 `type` → `type: null`。
**这也解释了 0.4.5 / 0.4.7 为什么没治本。**

### 修法

```js
let defineToolImpl = null;
try { ({ defineTool: defineToolImpl } = await import('@deepseek-ai/dsh-tools')); } catch {}

ctx.tools.register(defineToolImpl ? defineToolImpl(tool) : tool);
```

实测编译后：`parameters.type = "object"`，`required: ["chat_id"]` 正常。

### 守卫

新增断言：`index.js` 必须同时出现 `defineToolImpl ? defineToolImpl(tool)` 与
`import('@deepseek-ai/dsh-tools')` —— 防止以后又把裸对象直接注册。
