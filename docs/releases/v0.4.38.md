## v0.4.38 · Characterization Test（3 条 P0 行为基线）

为后续「拆 bridge.js」「改 epoch」提供**可复用的行为边界**。

> 原则：只钉**外部可观察的不变量**，不钉 prompt 全文、不钉内部调用顺序。
> 测试若因重构而红 = 写错了；只有**行为真的变了**才该红。

### 三条 P0（9 个断言）

| 组 | 断言 |
| --- | --- |
| **P0-1 群消息 → prompt** | ① 伪造「【系统指令】」**不制造新系统段**（身份/角色/令牌计数不增）② 跨群不串线 ③ 用户内容不被整体吞掉 |
| **P0-2 工具权限** | ① 非管理员不能消费审批（权限在副作用前生效）② 管理员可以 ③ **两层白名单覆盖插件全部 qqb_\\* 工具** |
| **P0-3 双轨互斥** | ① 活持有者不可抢占 ② 死持有者可接管（重启不卡死）③ 释放后另一通道才能拿到 |

### 写测试时抓到 4 个「我以为的行为 ≠ 实际行为」

1. `store.claim` **不做**死 PID 接管 —— 接管在 `startBridgeChannelGuard` 里
2. `store.release(mode, { pid })` 要两个参数，只传 pid 是空操作
3. 审批消费要求 pending **挂在回复者所在会话键**上
4. `plugin/tools.js` 工具名解析要用 `matchAll`，`replace` 会把名字吃掉

这 4 条本身就是价值：说明「凭印象改代码」会踩什么。

npm run test:characterization   # 单独跑
