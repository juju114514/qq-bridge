## v0.4.0 · 可以装进 DSH 了（插件模式）+ 群记忆交接

> **新增形态，不是替换**：`start.bat` 的常驻模式完全没变，行为一致。
> 无破坏性变更，默认配置下行为与 0.3.2 完全相同。

### 插件模式

把 QQ 通道装进 DSH 进程（`plugin add`），消息通路跟宿主同生命周期，不用再单独守护一个通道进程。
工具从 MCP 改成**进程内注册**，少一跳、少一个进程。

已提供 8 个工具：

| 工具 | 作用 |
| --- | --- |
| `qq_send_message` / `qq_reply` | 发消息 / 引用回复 |
| `qq_get_recent_messages` / `qq_get_unread_messages` / `qq_wait_for_messages` | 读最近、读未读、等新消息 |
| `qq_get_prompt` | 人格卡 + 人物印象 + **群记忆交接** |
| `qq_mark_read` / `qq_ping` | 已读水位 / 自检 |

**默认 `enabled: false`** —— 装上不等于连 QQ，必须显式打开。

### 群记忆交接（§〇）

每个会话一份 `state/memory/<key>.md`，`## §〇 交接` 覆盖写，**≤4 KB**，四个固定子项：
上次聊到哪 / 当前话题 / 记忆变更 / 下一步想聊。

解决的问题：**换模型、重启之后像失忆**。原则是「记忆在文件里，不在会话里」。

### sidecar 契约

`GET /health`、`GET /snapshot?key=`（带 ETag，命中回 304）、`POST /events`、`POST /intents`。

插件只读快照、只发意图；`state/` 仍由常驻进程单写 —— 不会两边互相覆盖。

### 通道互斥

`state/channel-mode.json` 带心跳认领：同一份 `state/` **只允许一个东西收 QQ 消息**。
bridge 被占用时**不连网关**（控制台与工具照常），日志直接说要先停插件；心跳过期（崩溃残留）可被抢占。

### 验证

- 审计 **126 个脚本**全绿（新增 8 个插件相关测试）
- 一致性闸：会话 key / 文本抽取 / 白名单 / @ 判定 / 去重 / 自己发的，两种形态结果一致
- 真机实测：`/health`、`/snapshot`（ETag 304）、`/intents`（交接落盘）、通道认领冲突

### 已知限制

- 表情包 / 语音类工具仍在 MCP 侧，插件模式暂未覆盖（下一版）
- 插件模式下**主动消息 / 定时提醒 / 控制台需要 sidecar 在跑**；不开只有被动回复
- 装插件验证时**一定要用独立的 `DSH_HOME`**，否则会和桌面版抢 `~/.dsh`

### 升级方式

无常驻模式改动，直接替换代码重启即可。想试插件模式看 [docs/guides/PLUGIN-MODE.md](https://github.com/juju114514/qq-bridge/blob/main/docs/guides/PLUGIN-MODE.md)。

node scripts/test-audit.mjs      # 126/126
node scripts/check-privacy.mjs
