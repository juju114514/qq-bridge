## v0.4.49.2 · guard 回收协议（第二轮复核 P2-1/P2-2 + P3）

复核结论：heartbeat/release 修复有效；但 **guard 自身的回收协议**有两个新缺口。本版只修这两个 + 两个 P3。

### P2-1 并发回收会删掉别人刚新建的 guard

旧代码检查 stale 后直接 `rmSync`，**没验证删的还是刚才检查的那个文件**。

现在：`rename` 抢占 → 比对 `ino/dev/birthtime` → 是自己检查过的才删；不是就**原样还回去**。

### P2-2 空/损坏 guard 被当作死持有者

1. **创建也原子化**：先写 pid 到临时文件，再 `linkSync` 挂到 guard 名 —— 消除"已存在但内容为空"的窗口
2. **读不到 pid 不再回收**：`holderPid <= 0` 一律保守拒绝（复核明确要求）

代价：guard 真损坏会一直等 → `TROUBLESHOOTING.md` 写了**手工删除步骤**（先确认没有第二个实例）。

### P3

| 项 | 改动 |
| --- | --- |
| beat 静默跳过 | 新增 `stats()`：连续失败计数 + 限流日志（第 3 次 / 每 30 次）+ 锁被接管事件 |
| 发送失败日志 | `.catch()` 改用 `describeError()`，不再输出异常正文 |
| verbose 开关 | 写进 `TROUBLESHOOTING.md`：设置、风险、用完必须删 `plugin.log` 与 `.1` |

### 测试：5 → 9 条

新增**真实双进程屏障**（A 在 guard 内忙等，B 认领必须失败）、空 guard 不回收、并发回收不误删、beat 计数可观测。

同时把上版命名不准确的用例改为「A 子进程持有实例锁时 B 认领被拒」。
