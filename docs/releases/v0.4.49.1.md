### R49-01：heartbeat/release 与认领的 TOCTOU

复核给出的准确序列（比我自审时更精确）：

```
1. A 的 heartbeat/release 读到"锁还是我的"
2. A 在写入/删除**之前**被暂停
3. B 在 A 心跳过期后接管，写入 B 的锁
4. A 恢复，按旧状态写/删 → 覆盖/删除 B 的锁
```

| 改动 | 说明 |
| --- | --- |
| `beat()` 进 guard | 「读身份 → 写」同一临界区 |
| `release()` 进 guard | 同上；删前比对 token |
| **generation token** | 认领时 `crypto.randomUUID()`；beat/release 必须比对，不再只比 pid+instanceId |
| guard 回收 | 「mtime>5s」→「mtime>5s **且** 持有者 pid 已死」 |

新增 `test-instance-lock-toctou.mjs`（5 条，含真实双进程屏障 + 「心跳不得覆盖新锁」确定性用例）。
