## v0.4.41 · buildId + ownerId + 健康聚合

> 不动 `bridge.js` 主体结构，只补「运行时跑的是什么、是谁、活着没」。

### ① buildId 取代「commit 当指纹」

真机实测：同步文件后部署目录的 `.git HEAD` 不变 → 指纹失效（之前截图显示 0.4.38 就是这么来的）。

```json
{ "buildId": "sha256:<64 hex>", "sourceCommit": "929f29a7de1a", "version": "0.4.41" }
```

- `buildId` = 运行时清单（`src/`、`plugin/`、`dsh/agent-presets/`）的**内容哈希**（路径+内容）
- 排除 `state/`、`logs/`、`node_modules/`、`.git/`、文档
- 跨仓库同内容 → 同 buildId；改文档不变；改代码必变

### ② ownerId + procStart（PID 会被重用）

```json
{ "schemaVersion": 2, "mode": "bridge", "pid": 24668,
  "ownerId": "6f998021-…", "procStart": 1793435403385, "epoch": 6, "status": "active" }
```

- 同一进程 heartbeat：ownerId / epoch 不变
- **同 PID 不同 ownerId → `pid-reused`：视为新持有者，epoch +1**
- v1 记录平滑升级：续期时补 ownerId，不误判死亡、不重置 epoch

### ③ `/health/detail`：连接状态与所有权分开

```json
{ "process": { "status": "running", "pid": 14532, "ownerId": "…" },
  "channel": { "mode": "bridge", "epoch": 6, "status": "active" },
  "services": { "dsh": "connected", "snowluma": "connected",
                "official": "connected", "console": "connected" },
  "live": true, "ready": true }
```

- 状态：`starting | connected | reconnecting | degraded | stopped | failed`
- **`live`** = 进程活着；**`ready`** = 持有通道 + DSH 连上 + 当前通道连接正常
- Official 连着但没持有通道时：`services.official=connected`，`ready` 仍按通道判定

### 测试 8 条（全绿）

```
① 相同代码不同 Git HEAD → buildId 相同
② 只改运行代码 → buildId 变
②-b 只改文档 → buildId 不变
②-c state/ 与 node_modules 不进 buildId
③ 同一 PID、不同 ownerId → 旧进程不能继续持有（epoch+1）
③-b v1 记录平滑续期（不误判死亡）
④ DSH connected → reconnecting → connected，ready 跟随
④-b 通道未持有 → ready=false
```
