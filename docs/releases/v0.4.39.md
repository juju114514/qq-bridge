## v0.4.39 · 双轨 epoch（fencing token）+ 副作用边界守卫

> 只做 epoch / 所有权 / fencing：**不拆 bridge.js、不改 prompt 行为**。

### 状态结构

```json
{ "schemaVersion": 1, "mode": "bridge", "pid": 24668,
  "epoch": 1, "status": "active", "at": 1793434238476, "note": "sidecar 通道" }
```

- `epoch` 是 **fencing token**：重新取得所有权 +1；**同一持有者续期不 +1**
- 新增 `state/channel-mode-epoch`：**只增不减的 epoch 水位**
  → 即使认领文件被删，epoch 也不会从 12 退回 1，旧任务永远无法「碰巧匹配」
- `release()` 不再删文件，改 `status: "released"`（保留 epoch，清空 pid）

### 原子更新 + 跨进程互斥

- 复用仓内唯一实现 `src/atomic-write.js`（唯一临时名 + EPERM/EBUSY 退避重试）
- 新增 `state/channel-mode.lock`（`wx` 创建、>5s 残留可抢、最多重试 200ms）
- `claim / heartbeat / release` 全部 `withLock(read → 改 → 原子写)`，杜绝「读旧快照再递增」

### 副作用守卫

| 位置 | 过期时 |
| --- | --- |
| DSH 提交前 | **不提交**（返回 `{stale:true}`） |
| QQ 发送前 | **不发送**，标记该 key 失败 |
| 记忆写入前 | **不写记忆** |

> 诚实说明：校验到副作用之间仍有**毫秒级竞态窗口**。它不是原子操作，
> 只把窗口从「整段处理」压到最小；真正的串行化靠「单通道持有」这个前提。

### 测试 7 条（全绿）

```
⑦ 旧 epoch 不执行工具
```
