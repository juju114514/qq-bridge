## v0.4.42 · 生命周期规范 + 结构化启动摘要 + Windows 重启根因

> 只有文档、摘要与少量脚本改动，**不拆 bridge.js**。

### ① `docs/STARTUP-LIFECYCLE.md`

六个阶段（启动 / 认领 / 连接 / 就绪 / 运行 / 关闭），每阶段：谁负责、失败怎么办、允不允许 ready。
顺序按**代码实际跑出来的**（指纹先于认领；释放所有权必须在保存状态之后）。

`ready` 只看「持有通道 + DSH + 该通道连接」，**不是**「所有服务都 connected」。

### ② 结构化启动摘要


- 第一次 `ready=true` 打；10 秒兜底；只打一次
- 失败留证：`startup.incomplete`（reason + aborted 阶段）
- **不含凭证**

### ③ 关闭顺序

```
draining → saveState → shutdown.summary → 释放通道 → releaseLock → exit
```

释放所有权**必须最后**：否则别人立刻接管，而旧进程还在写 `state/`。

### ④ Windows「窗口自动重启」根因

| 证据 | 结论 |
| --- | --- |
| `node ← powershell ← svchost` | 计划任务拉起 |
| `RestartOnFailure=PT1M × 999` + 无隐藏窗口 | **每次任务实例结束 → 1 分钟后重拉可见窗口** |
| `runner.log` 只有启动行、没有退出行 | 不是脚本循环，是整进程被结束 |
| 间隔 42–49 秒 | 与 `PT1M` 吻合 |

**修法（需管理员执行一次）**：

```powershell
cd D:\deepseek工作区\qq-bridge
powershell -ExecutionPolicy Bypass -File scripts\harden-scheduled-task.ps1 -Apply
```

关掉 RestartOnFailure / 加 `-WindowStyle Hidden` / `MultipleInstances=IgnoreNew` / 无超时。
普通权限执行会 `Access is denied`（这是预期）。
