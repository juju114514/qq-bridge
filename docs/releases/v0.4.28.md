## v0.4.28 · Official 通道专项审计

回答一个问题：**官方通道到底是不是同一套系统，还是只共用了 DSH API？**

### 结论：是同一套核心

```
官方消息 → handleIncoming(kind, id, oneBotEvent)   ← 与 SnowLuma 同一个函数
        → convKey → socialV2 → 会话/记忆/prompt/人设/黑话/控制台 全部共用
```

代码证据：`bridge.js` L9869 分派点、`official-transport.js` L38 `toOneBotEvent()`。

### 但有 3 个真实缺口

| # | 缺口 | 后果 |
| --- | --- | --- |
| 1 | `selfDisplayName/selfUserId` 只在 SnowLuma 登录时赋值 | prompt 告诉模型「你是 3976372760」——那是个人号，不是官方机器人；只跑官方通道时身份行整段消失 |
| 2 | `ownerQQ` 是数字，官方 `user_id` 是 openid | **管理员在官方通道没有任何管理能力**（审批/切角色/封闭模式全失效） |
| 3 | 官方入站 `msgSeq` 恒为 0，且未按 `message_id` 去重 | 重连重投时可能重复处理、重复回复 |

### 修复优先级

1. 官方通道写入正确身份（半天）
2. `official.ownerOpenid` → owner 判定支持 openid（半天）
3. 按 `message_id` 去重（2 小时）
4. 文档补「记忆键是 openid，与个人号是两份」（1 小时）

**上线前必须修 1 与 2。**
