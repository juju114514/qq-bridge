# ⚠️ 安全修复：插件模式下群友可越权操作本机

## 漏洞

插件模式早期版本建 agent 时**没挂 `agentPreset`**，agent 拿到的是 DSH 默认工具集
（`pwsh` / `read` / `write` / `edit` / `subagent` …），**权限等于用户本人**。

群聊消息来自陌生人 —— 任何群友 @ 它一句，就能让它读写本机文件、执行命令。

真机已发生：群友要求"管理员级操作"，agent 照做。

## 为什么桥接模式没这个问题

桥接走 `qq-chat-v2` preset，里面 `qq-tool-restrict` 有两道：

- 注册期 `tools.restrict()` 把本地工具从 schema 隐藏
- 执行期 `tools.guard()` 白名单兜底（`ask_user_question` / `todo_write` / `mcp__snowluma__*` / `mcp__web-search-safe__*`）

插件模式绕过了整条链路。

## 修法（两层）

| 层 | 位置 | 效果 |
| --- | --- | --- |
| 工具白名单（注册期） | 插件 `tools.restrict({ allow: [...] })` | 只留 `qqb_*` + `todo_write` + `ask_user_question` |
| 执行期 guard | `agentPreset: qq-chat-v2` | 越界调用直接拒绝 |

启用插件模式后**必须**确认 `plugin.log` 有这两行，否则不要交出通道：

```
已对 agent 应用工具白名单（10 个；本地工具全部不可见）
agent 已建：preset=qq-chat-v2 cwd=…
```

**尽快升级。** 如果你的插件模式曾经启用过（`enabled: true`），建议：
1. 检查那段时间群里的指令与 agent 的回复
2. 确认没有实质性的文件/命令操作
3. 升级后按上面的两行日志验证白名单确实生效
