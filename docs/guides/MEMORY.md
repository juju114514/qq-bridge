# 长期记忆（LivingMemory 式结构）

> 来源：AstrBot 的 [LivingMemory 插件](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 给了很好的结构参考。
> 我们**没有移植它**（那是 AstrBot 插件，运行时不同），而是把其中真正有用的部分落成了 200 行纯函数：
> 权重、衰减、命中强化、打分检索、合并、归档。

---

## 一、为什么需要它

升级前的记忆只有三种粗糙机制：

| 现状（v2） | 问题 |
| --- | --- |
| `activeTopics` **24 小时没提就删** | 没有长期记忆——上个月的事一定忘 |
| 容量截断（20/10 条） | 记忆一多就靠硬砍 |
| 只有 `lastMentionAt` | 一句玩笑和一条约定**权重相同** |

## 二、结构

```
原子 atom = {
  text:       事实正文（如「周五四点交作业」「小明：爱熬夜」）
  tags:       ['话题' | '群友' | ...]
  weight:     基准权重（初始 1，命中 +0.3，封顶 3）
  createdAt:  创建时间
  lastHitAt:  最近一次被检索命中 / 更新的时间
  hits:       命中次数
  source:     来源（会话 key 或 legacy:xxx）
}
```

存储位置：`state/social-v2.json` 每个会话的 `longTermMemories[]`（最多 200 条，超出淘汰最弱）。

## 三、四个公式

| 机制 | 公式 | 效果 |
| --- | --- | --- |
| **衰减** | `有效权重 = weight × 0.5^(天数/30)` | 半衰期 30 天；半年没提≈忘掉 |
| **强化** | 命中时 `weight = min(3, weight+0.3)`，`hits++` | 越常被提起越牢 |
| **打分** | `0.6×关键词覆盖 + 0.3×归一化权重 + 0.1×新鲜度` | 相关 > 重要 > 新鲜 |
| **合并** | 词集 Jaccard ≥ 0.6 视为同一条，`weight+0.2`、`hits+1` | 防止同一件事刷屏 |

中文没有空格：CJK 取**二元组**、英文取整词、数字保留（`tokenize()`）。

## 四、注入预算（硬约束）

`GET /api/socialV2/memory` 现在返回两段：

1. `formatMemoryV2(st)` —— 原有三块（进行中话题 / 想说没说 / 对群友印象）
2. `formatLongTerm(...)` —— **【记得的事】** top-K

预算：**最多 6 条、合计 800 字**，超预算时优先塞短条目（不硬截断语义）。
支持 `?q=<文本>` 按查询排序；不传则按"权重×新鲜度"排。

## 五、迁移

老会话没有 `longTermMemories` 时：**读取端点现场合成**（`migrateFromLegacy`，只读不写盘），
所以升级后立刻能看到旧话题/旧印象；第一次写入时才会真正落盘。

`pendingThoughts` **不迁移**——它是两小时内的临时物，不属于长期记忆。

## 六、归档

`archiveAtoms()` 把有效权重 < 0.05 的原子分出（冷数据）。当前策略：容量超限时直接淘汰，
归档接口留给后续"冷存 + 检索回捞"用（未接线，避免过度设计）。

## 七、已知取舍

| 取舍 | 原因 |
| --- | --- |
| **不做向量检索** | 要 embedding 服务（成本/隐私），群聊记忆以"人和事"为主，关键词+衰减够用 |
| **不做图谱** | 关系用 `memberImpressions` 表达，比抽实体关系稳 |
| **不做自动总结（P2）** | 需要一次 LLM 调用；当前靠模型主动 `qq_memory_append`，先观察噪音再上 |
