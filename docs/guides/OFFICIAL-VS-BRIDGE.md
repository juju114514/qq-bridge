# 官方插件 vs 本仓库：两条路怎么选

> 2026-10-31，QQ 官方发了一条"三步把 DeepSeek 接进 QQ"的推广：
> 装 DSH 客户端 → 插件里装 `@tencent-connect/dsh-qqbot@latest` → 扫码绑定。
>
> 这条路**确实存在、也确实最简单**。本文把它和本仓库（qq-bridge）摆在一起说清楚：
> 各自能做什么、代价是什么、什么时候该选哪个。**不带营销，只讲限制。**

## 一、官方插件是什么（实测信息）

| 项 | 值 |
| --- | --- |
| 包名 | `@tencent-connect/dsh-qqbot`（v0.5.5，MIT） |
| 仓库 | <https://github.com/tencent-connect/dsh-qqbot> |
| 协议 | QQ Bot API v2（官方机器人通道，不是个人号） |
| 形态 | 纯 Cordis 插件，`inject = ['agents']`，装在 DSH 的 profile 里 |
| 绑定 | 桌面版：设置 →「QQ 机器人」→ 手机 QQ 扫码，凭据自动存进 `cordis.patch.yml`，后续不用再扫 |
| 能力 | 会话隔离（每私聊/群一个 Agent）、preset、`/model` 切模型、Markdown、图片理解（`qqbot_describe_image`）、发文件、`ask_user_question` 内联按钮、审批按钮、私聊流式 |
| 默认 | `requireMention: true`（群里必须 @ 才回）、群历史缓冲 **10 条**、闲置 30 分钟回收 |

**关键点**：它用的是**官方机器人号**，所以**没有封你的个人 QQ 的风险** —— 这是它最大的优势。

## 二、两条路的真实差异

| 维度 | 官方插件（`dsh-qqbot`） | 本仓库（qq-bridge） |
| --- | --- | --- |
| 接入难度 | **3 步**（装 DSH → 装插件 → 扫码） | 8 步（DSH + SnowLuma/NapCat + 配置 + 启动） |
| 账号风险 | ✅ **无**（官方机器人号） | ⚠️ 有（第三方程序登个人号，可能被限制/封号） |
| 能看到多少群消息 | **只有 @ 它的**（默认）；群主可开"接收全量消息" | **全部**（个人号视角，群友说啥都看得见） |
| 能不能主动插话 | ❌ 不能（被动回复，有 5 分钟窗口限制） | ✅ 能（唤醒调度、潜水接话、主动搭话） |
| 表情包 / 斗图 | ❌ 无 | ✅ 收藏表情、按情绪挑、斗图 |
| 语音 / 唱歌 / 点歌 | ❌ 无 | ✅ `qq_say` / `qq_sing` / `qq_song` |
| 人格卡 | ⚠️ 靠 preset / prompt，没有"角色卡文件 + 控制台切换" | ✅ `roles/*.md` + 控制台切人格 |
| 记忆 / 人物库 | ⚠️ 靠会话上下文（30 分钟闲置回收） | ✅ 长期记忆 + 人物库 + 黑话库 |
| 控制台 | ❌ 无（只有斜杠命令） | ✅ 12 页控制台（状态/人物/黑话/定时任务/令牌花费…） |
| 定时任务 | ❌ 无 | ✅ `/提醒` + 调度引擎 |
| 红包 / 转账识别 | ❌ 无 | ✅ |
| 多网关 | ❌ 只走官方 | ✅ SnowLuma / NapCat 可切 |
| 成本 | 官方机器人与模型费用 | 同上 + 第三方登录的隐性风险 |

**一句话**：官方插件是**客服型机器人**（@ 才答、答完就完）；
本仓库是**群友型机器人**（看得见全场、会潜水、会插话、会斗图）。

## 三、怎么选（决策树）

```
你只想让 AI 在群里回答问题？
  └─ 用官方插件。3 步搞定，没有封号风险，别折腾本仓库。

你想要的是"群里有个人"——会潜水、会接梗、会斗图、会突然冒一句？
  └─ 本仓库。但先想清楚：个人号登第三方程序有封号风险，用小号。

两个都要？
  └─ 可以共存：官方插件管"问答"，本仓库管"陪聊"。
     注意别让两边回同一句话（各自绑定不同的号 / 不同的群）。
```

## 四、安全提醒（QQ 官方原话，我们完全同意）

> 请通过 QQ 官方教程接入 QQ Bot，谨慎使用未经 QQ 授权的第三方工具，
> 以免造成账号信息泄露、聊天隐私被窃取、账号被冒用发送消息等安全风险，
> 还可能导致账号功能受限甚至被封禁。

本仓库就是"第三方工具"那一类（SnowLuma / NapCat 登录个人号），所以：

- **我们从来不说"没有风险"** —— 文档里一直写着用小号、`RULES.md` 里有安全边界
- 如果你不能接受这个风险，**请直接用官方插件**，这不是丢人的选择
- 如果两者都用：给本仓库单独的号，别和官方机器人共用

## 五、本仓库的官方通道（第三条路）

本仓库自己也有官方通道实现（`src/qqbot-official.js` 等），走同一套 API v2，
但**需要自己去 q.qq.com 申请 AppID/AppSecret**（个人主体只能加自己管理的群）。
如果你已经装了官方插件，就不需要再用我们的官方通道 —— 功能重叠。
