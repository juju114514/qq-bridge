## 三、场景 G 抓到的真问题（已修）

`consolePort` 在 `src/config.js` 里是**原样透传**的：

```js
consolePort: file.consolePort ?? (Number(process.env.QQB_CONSOLE_PORT) || 3100)
```

于是 `"abc"` 一路走到 `http.listen()`，变成：

```
控制台服务错误: listen EACCES: permission denied abc
```

**桥接照常在跑，但控制台永远打不开** —— 而日志里只有一句莫名其妙的 EACCES。

修法：加载阶段校验，`0`（随机端口）与 `1~65535` 合法，其余直接抛：

```
启动失败: Error: config.json 的 consolePort 无效："abc" —— 必须是 0（随机端口）或 1~65535 的整数端口（例如 3100）
```

新增 `scripts/test-config-dirty.mjs`（7 条断言，已登记进审计）覆盖：
顶层非对象、缺省 3100、数字/字符串数字、**0 = 随机端口**、脏值报错、空串回退、consoleHost 缺省。

## 四、过程中的一次事故（记录）

收尾清理沙箱进程时，我按"命令行含 `src\bridge.js` 且不含 `deepseek工作区`"过滤 ——
但真机进程也是用 `-WorkingDirectory <live>` + `src\bridge.js` 启动的，**命令行里没有 `deepseek工作区`**，
于是**真机也被杀掉了**（3100 直接拒绝连接）。已立即重启恢复（04:17:27，pid 7064，reserved2，paused=false）。

**教训：按命令行区分进程不可靠，要按"谁占着哪个端口"判断。**
沙箱 3199、真机 3100 —— 用 `Get-NetTCPConnection -LocalPort` 找 OwningProcess 才是准的。
