## 一、它到底是什么

不是软件，是**一套多场景 AI 工作台的搭建方法与纯壳模板**。README 自己就写了
「这不是装完就能用的软件，文档路径全是占位符，照抄一定失败」。

真正有料的是它的**分层与记忆规则**，正好是我们现在缺的那类"结构"而非"功能"。

## 二、核心模型：六层，每层只有一个真源

| 层 | 放什么 | 谁能写 |
| --- | --- | --- |
| **L0 宪法** | 铁律与附则，版本化（改一次 +1，旧版留档） | 只有宿主 |
| **L1 共享层** | 宿主画像 / 场景区域表 / 项目清单 / 通知待办 / 总索引 / 体检快照 | 分区写，各 owner 只写自己的 |
| **L2 场景私有** | 私有记忆（§〇 交接）/ 身份卡 / 场景画像 / 项目记忆 / 专属技能 / 归档 | 只有本场景 |
| **L3 个人层** | 个人档案与知识库 | 本人及授权者，**不进共享层** |
| **L4 运行时** | 引擎 / 工具 / MCP / 插件 / 计划任务 | 专人维护；工具放代码仓外，升级不破坏数据 |
| **L5 归档** | 备份 / 会话冷备 / 场景归档 | **只进不改**，可恢复 |

判据一句话：**每个东西只属于一层，只在一个地方是真源；其他地方只放指针。**

## 三、记忆规则（最有价值的部分）

1. **每轮注入只放"不读就会白干的铁律"，必须极短**
2. **场景私有记忆**：`§〇 当前交接` **覆盖写**（上次交接 / 当前项目表 / 记忆变更 / 下一步与卡点），**≤4 KB**；
   主文件 **≤25 KB**
3. **项目记忆**：一个项目一份，**≤8 KB**，字段固定（状态 / 一句话 / 成果证据 / 下一步 / 坑 / 已有档案）
4. **换会话前先写交接 → 跑 `场景记忆 check` → 不过不许换**；旧版进归档
5. 核心心法：**记忆在文件里，不在会话里** —— 所以会话可以无限换，场景不会失忆

还有两条协作铁律值得记：
- **只许请求，不许改对方记忆**：命令台只做路由；改谁的记忆只归谁
- **反例验收**：校验类工具必须能证明"该失败时会失败"

## 四、和我们的对照：我们缺什么、已经有什么

| 它的做法 | 我们的现状 | 结论 |
| --- | --- | --- |
| 全局注入极短 | 我们在**每轮注入 23 KB 人格卡** | ⚠️ 已做 `roleInjectEvery` 缓解；它还提示"该拆成宪法 + 按需" |
| 记忆在文件里 | `state/people.json` + 群记忆 + DSH 会话 | ✅ 方向一致 |

| 六层权限 | 我们有 `check-privacy` / 单写者约束 | ⚠️ 概念有，没写成规则 |

## 五、建议借的三件东西（都能落到我们现在的工作里）

### 1. 人格卡拆两层：宪法（极短）+ 场景卡（按需）

现在的 23 KB 人格卡里，真正"不读就会白干"的规则大概 1~2 KB（禁止项、安全边界、语气底线）。
其余是梗、示例、场景指令 —— 应该走"按需注入"。

**落到哪**：`socialV2.roleInjectEvery` 已在做的方向；下一步可做 `roles/*.md` 的小节标记
（`〔常驻〕` / `〔按需：唱歌〕`），我们已有 `selectRoleText` 的按需机制，接上即可。

### 2. 群记忆里的"交接"段（≤4 KB，覆盖写）

每个群一份 `state/memory/<key>.md`，含：
`上次聊到哪 / 当前话题表 / 记忆变更 / 下一步想问什么`。

**价值**：换模型、换会话、重启之后，AI 不用重新"摸一遍群里的气氛"。
**落点**：N2 的 `/snapshot` 可以顺带把它读出来（否则每轮重建代价更高）。

### 3. 文档模板固定字段：状态 / 一句话 / 证据 / 下一步 / 坑

我们的 `docs/validation/*`、`docs/audits/*` 现在各写各的。
固定字段后，人和 AI 都能"扫一眼就知道结论"，也方便以后做索引。

## 六、明确不抄的

| 不抄 | 原因 |
| --- | --- |
| Electron 外壳与启动链路 | 我们用 DSH 桌面版，多一层壳只会多一处坏 |
| 「文档路径全是占位符」的写法 | 对新手是灾难；我们的 `BEGINNER.md` 走的是可复制真实命令 |
| 规模数字（十余场景/二十余技能） | 作者自己都说"不构成承诺" |
| 密集的 `配图/*.svg` 拓扑图 | 维护成本高，收益偏"看得爽" |

## 七、一句话结论

**这套东西的价值在"结构"不在"功能"**：它没有教我们写什么代码，
但把「记忆该分几层、每层谁写、换会话怎么办」讲清楚了 —— 而我们恰好在这一块只有零散约定，没有规则。

**优先级**：先做第 2 件（群记忆交接），因为它直接改善"换模型后像失忆"这个真实痛点，
而且和正在做的 `/snapshot` 是同一件事；第 1、3 件排后面。
