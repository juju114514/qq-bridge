# 参考评估：飞书《用 Skill 一键装大肥鱼（第二期）》

> 来源：用户 2026-10-31 睡前发来的一篇飞书云文档（作者「泽轩604」，同系列抖音视频的配套文档）。
> 本文只记录**我们借鉴了什么、不借鉴什么**，不复制原文。

## 一、它的核心做法

| 它怎么做 | 说明 |
| --- | --- |
| **Skill = 给 AI 看的安装手册** | 不是安装包，而是一份文档；用户把它交给一个能执行命令的 AI 助手，助手照着手册装 |
| 用户只在几处动手 | 填 key、粘东西、扫码、点确认 —— 其余全自动 |
| 手册会随问题更新 | 他们测出问题就改 Skill，用户"每次下到的都是最新版" |
| 明确标注「没实测」的地方 | 没亲手走通的步骤单独标出来，让用户以屏幕为准 |
| 风险声明前置 | 第三方程序登 QQ 不符合用户协议、小号可能被封、群消息会被处理 |
| 五项功能验收 | 装完不是"能启动"就算，而是逐项验：会说话 / 发语音 / 记得你说过的事 / 有身份 / 会看图看视频听语音 |

## 二、我们借鉴了什么（已落地）

新增 **`docs/guides/INSTALL-SKILL.md`**（192 行），结构对齐它的思路，但内容全部基于**我们仓库的真实脚本与路径**：

1. **给 AI 的开场白**（可直接复制）——含四条硬约束：
   先说要做什么 / 需要人手做的停下来等 / **不要打印 token** / 卡住按自愈顺序
2. **阶段 0→7**：体检 → 取代码 → 装依赖 → `first-run.ps1` → 填 `ownerQQ`+`allow.groups`
   → 两个外部程序（标注「🚧 需要用户亲手」）→ 启动 → 验收
3. **"AI 能做的 / 用户必须做的"分栏表**：把"人不该被 AI 代替"的动作明确划出来
4. **自愈顺序**（5 步，不许跳步、不许重复同一失败命令）
5. **风险声明**：账号风险 / 消息可见性 / 密钥 / 费用
6. **末端解释"为什么是 Skill 不是安装包"**：安装包体积大、平台绑死、报错不会解释；
   Skill 让 AI 现场判断（路径不同、杀毒拦截、端口漂移都能自己改动作）

入口：`README` 顶部、`BEGINNER.md` 顶部、`docs/README.md` 索引都指向它。
零基础指南（八步）保留 —— 不想把电脑交给 AI 的人仍然可以照着点。

## 三、我们没有照抄的部分（以及原因）

| 它的做法 | 我们的选择 | 原因 |
| --- | --- | --- |
| Skill 托管在飞书/远端，"每次下到最新版" | **放在仓库里，跟版本走** | 手册里的命令必须和代码同一版本；远端更新会让"手册说 A、代码是 B" |
| 用豆包语音 / 硅基流动 key 做语音 | 已有 `voice-tool` 与 `qq_say` 两条链路 | 我们的语音是本地工具 + 桥接 CLI，不引第三方 TTS 依赖 |
| NapCat / SnowLuma 二选一由 AI 装 | 文档写清两者差异，**安装仍由人做** | 两者都要扫码登录，AI 代劳不了；提前说清比"装到一半卡住"好 |
| 五项功能验收 | 我们拆成 `自检.bat`（12 项环境）+ 群里 @ 一次 | 环境问题和"功能没启"要分开定位，混在一起新手分不清 |

## 四、可以再吸收的两点（待做）

1. **功能级验收清单**：它按"会说话 / 发语音 / 记得你 / 有身份 / 会看图"逐项验。
   我们目前只验"能启动 + 能回话"。可以加一份 `docs/guides/VERIFY-FEATURES.md`：
   每项给一条**可复制的最小验证命令**（发一条语音、贴一张图、问一句"我是谁"）。
2. **「没实测」的显式标注规范**：他们标得比我们狠。
   我们可以把 `docs/validation/` 里的"未覆盖"字段固化成模板字段（`未实测：…`），
   让读者一眼看到边界。

## 五、结论

**有参考价值，而且正是我们缺的那一块**：我们写了"人怎么一步步装"，它补上了"让 AI 替你装"这条路。
已按我们的实际情况落地成 `INSTALL-SKILL.md`，没有照抄内容，也没有引入它的外部依赖。
