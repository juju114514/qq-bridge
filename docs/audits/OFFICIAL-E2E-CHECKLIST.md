# 官方通道 e2e 验收清单与记录模板

> 用途：LOCK.md 的解锁条件③要求「真机 e2e 四条全过」。这份清单把每条拆成**可执行步骤 + 要留的证据**，
> 跑完把结果填进最后的记录表，放进 `docs/audits/`。
>
> 前置：`official.enabled=true`、appid/secret 已配、`official.allow` 至少含目标群 openid。
> 建议先配 `official.ownerOpenid`（见 §二）。

---

## 一、四条 e2e（LOCK.md 口径）

| # | 验收项 | 步骤 | 通过标准 | 要留的证据 |
| --- | --- | --- | --- | --- |
| 1 | 官方群 @ → 正确回复，且**只回一条** | 在已 allow 的官方群里 `@机器人 说句话` | 收到一条回复；**没有重复条** | `bridge.log` 里该次消息的 `[official]` 行 + QQ 截图 |
| 2 | 私聊收发正常 | 私聊机器人发一句话 | 正常回复 | `[official]` 收发行 + 截图 |
| 3 | 发图 → 能看图 | 发一张带文字的图片 | 回复内容体现出**读到了图里的内容** | 回复文本 + 图片 + 日志 |
| 4 | 不在 `official.allow` 的会话被拒绝 | 从一个**没加白名单**的官方群 @ 它 | 不回复，且日志写明拒绝 | 日志里对应的拒绝行 |

配套两项（LOCK.md 的 ②④，不是四条 e2e 之一但要一起验）：

| # | 验收项 | 通过标准 | 证据 |
| --- | --- | --- | --- |
| 5 | 身份正确 | 启动日志有 `[official] 自我身份已设置：显示名「官方机器人」`，且 prompt 里不是个人号 | 日志行 + prompt 片段 |
| 6 | 去重 | 断线重连后重投同一 msg_id 不再回复 | 日志出现 `[official] 重复消息，跳过` |

## 二、先把 `ownerOpenid` 配上（否则管理员指令在官方通道不生效）

官方通道**没有 QQ 号**，owner 用 `openid` 判。它没法猜，只能从一条真实私聊里取：

1. 让管理员用 QQ **私聊**一次机器人（随便说一句）
2. 看 `state/official-inbound.json`（每次入站会写一条）：

```jsonc
{"kind":"private","openid":"XXXX…","msgId":"…","at":1699…}
```

3. 把那个 `openid` 写进 `config.json`：

```jsonc
"official": { "ownerOpenid": "XXXX…" }
```

4. 重启后验证：用管理员私聊发 `/自检` 或管理指令，应生效（日志里 identity 标成 owner）。

> ⚠️ **别猜**：填错 openid 不会报错，只会让"owner 权限"静默失效。

## 三、跑探针（补齐闸门的 `probe` 项）

```powershell
# 建议先停桥接，避免同一个 bot 两条连接
schtasks /end /tn qq-bridge
node scripts\official-probe.mjs --seconds 120
# 成功会写 state/official-probe.json；再看控制台「运维 → 官方通道」清单应全绿
schtasks /run /tn qq-bridge
```

探针会打印：授权 → 网关 → （可选）主动消息。收不到事件时它会提示该查什么（是否加群、是否 @、群主是否开了"接收全量消息"）。

## 五、已知的官方通道限制（验收时别误判成 bug）

| 限制 | 说明 |
| --- | --- |
| 没有 QQ 号 | 身份是机器人，`openid` 取代 QQ 号；`allow` 与 owner 都按 openid 判 |
| 被动回复窗口 | 收到消息后约 4.5 分钟内必须回（`PASSIVE_WINDOW_MS`），超时要走主动消息配额 |
| 主动消息有配额 | 不是想发就能发；`official-proactive.js` 里是窗口逻辑 |
| 群要显式加它 | 不能被拉进任意群，也不能读历史消息 |
| 事件可能重投 | 所以需要去重（缺口 3 修的就是这个） |
| 需要主体审核 | q.qq.com 上的机器人有审核状态，沙箱 `sandbox=true` 与正式环境行为不同 |
